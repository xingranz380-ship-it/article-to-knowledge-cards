# Make Knowledge Cards

## Overview

将用户提供的文章（粘贴文本或本地 `.md`/`.txt` 文件）提炼为 5~8 张知识卡片。每张卡片聚焦一个独立知识点，包含标题、核心知识、简明解释、例子或自测问题，帮助用户快速复习和掌握文章重点。

## Workflow

### Step 1: 获取输入

- **粘贴文本**：直接使用用户消息中的文本内容。
- **本地文件**：用户提供 `.md` 或 `.txt` 文件路径时，用 Read 工具读取全文。
- 若输入是网页链接、PDF 或其他不支持格式，明确告知用户暂不支持，并请其粘贴纯文本或提供 `.md`/`.txt` 文件。

### Step 2: 通读与识别知识点

1. 完整阅读全文，理解文章主旨和结构。
2. 列出文中所有候选知识点（概念、原理、方法、结论、关键事实等）。
3. 按重要性排序：优先选择文章核心论点、反复强调的概念、支撑主旨的关键知识。
4. 合并重复或高度相似的知识点。

### Step 3: 筛选与数量控制

- 目标数量：**5~8 张**卡片。
- 若文章内容丰富，只保留最重要的 5~8 个知识点，舍弃次要细节。
- 若文章信息不足（如短文、纯叙事、缺乏可提炼的知识），**不要强行凑数**，可以生成少于 5 张卡片，并在末尾说明"原文可提炼的独立知识点有限"。
- 若原文是纯叙事、纯抒情、日记等完全没有可提炼知识点的内容，可以生成 **0 张**卡片，直接告知用户"本文为叙事/抒情类内容，缺乏可提炼的独立知识点，不适合生成知识卡片"。
- 每张卡片只讲**一个**知识点，不把多个概念塞进同一张卡片。但一组紧密相关、共同构成一个知识单元的子概念（如同一机制的多个组成部分、影响某事物的多种因素）可以放在同一张卡片中，前提是它们服务于同一个核心主题。

### Step 4: 生成卡片

对每个选中的知识点，按以下模板生成：

```
## 卡片 N：[标题]

**核心知识**：[一句话定义或最关键的结论，不超过 2 行]

**简明解释**：[2~3 句话解释该知识点的含义、原理或意义，用自己的话复述，不照搬原文长句]

**例子 / 自测问题**：[二选一]
- 例子：原文中出现的具体实例、应用场景或数据（必须来自原文）
- 自测问题：基于该知识点设计的一道简答题，帮助检验理解
```

**例子与自测问题的选择**：
- 原文中有具体实例、数据、应用场景时，优先使用**例子**。
- 知识点是抽象概念、原理、方法，且原文没有具体例子时，使用**自测问题**。
- 一张卡片只选其中一种，不要同时给出例子和自测问题。

### Step 5: 质量校验

输出前逐项检查：

- [ ] 每张卡片的知识点是否确实来自原文，没有编造？
- [ ] 是否有两张卡片讲了同一个知识点（重复）？
- [ ] 每张卡片是否只聚焦一个知识点？
- [ ] "例子"是否确实出自原文，而非自行编造？
- [ ] "自测问题"是否可以通过原文内容回答？
- [ ] 卡片数量是否在 5~8 之间（或信息不足时已说明）？
- [ ] 语言是否简洁，没有照搬原文大段文字？

## 核心原则

1. **只提取原文有的信息**：严禁编造原文未提及的概念、数据、例子或结论。若某个知识点原文解释不充分，如实简写，不补充外部知识。
2. **重要性优先**：选择文章真正想传达的核心知识，而非均匀摘录每段第一句。
3. **去重**：同一概念在文中多次出现时，只生成一张卡片，整合各处的解释。
4. **一卡一点**：一张卡片只讲一个知识点，避免"大杂烩"卡片。
5. **不强行凑数**：信息不足时宁可少做，也不把次要细节或原文没有的内容硬凑成卡片。

## 不支持的功能

- 网页抓取（不自动打开 URL 提取内容）
- PDF 文件解析
- 导出为 Anki 或其他闪卡格式
- 图形界面 / 交互式卡片展示

## 输出格式

直接在对话中输出 Markdown 格式的卡片，每张卡片用 `## 卡片 N：标题` 分隔。不需要生成文件，除非用户明确要求保存为 `.md` 文件。

**输出语言**：使用与原文相同的语言输出卡片。原文是中文则用中文，原文是英文则用英文，不要翻译。
